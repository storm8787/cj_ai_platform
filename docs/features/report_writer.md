# 업무보고 작성기

## 1. 기능 개요

- **목적**: 입력한 키워드·내용을 바탕으로 공문 형식의 업무보고 문서 자동 생성
- **사용 대상**: 충주시청 공무원 (계획보고, 대책보고, 상황보고, 분석보고 등)
- **처리 내용**: 보고서 유형 선택 → 내용 입력 → GPT-4o로 섹션별 보고서 생성

API prefix: `/api/report-writer` (main.py에서 등록)

| 메서드 | 경로 | 설명 |
|-------|------|------|
| GET | `/api/report-writer/structures` | 보고서 유형 및 템플릿 목록 |

## 4. 주요 데이터 흐름

1. 사용자: 보고서 유형 선택 (**5개 카테고리**, 각 3~4개 세부 유형 = 총 16개)
2. 필수 입력: 제목, 유형/세부유형, 핵심 키워드(쉼표 구분), 분량
3. 선택 입력: 부서명, 작성자, 보고일자, **확인된 사실(자유 서술)** — 비우면 키워드 중심 생성
4. GPT-4o로 섹션별 보고서 생성 (확인된 사실을 최우선 근거로 사용, 미확인 수치는 자리표시자 처리)
5. 후처리:
   - 종결어미 개괄식 변환 — **항목 내 모든 문장** 대상(날짜 `2026. 1. 15.`·소수 `3.2`는 문장 분리 제외)
   - 마크다운 불릿(`-`,`*`,`•`)만 제거하고 **개조식 번호(1. 가. 1) ①)는 보존**
   - 행정기호 보존(`「」 → ℃ ㎡ ① ※` 등), 천단위 콤마 삽입
6. 응답: `sections` 배열 (title, order, content) + 머리말 정보(department, author, report_date)
   - `content` 항목이 개조식 번호로 시작하면 프론트가 해당 번호로 렌더링(없으면 `❍`)

### 입력 필드 (`ReportGenerateRequest`)

| 필드 | 필수 | 설명 |
|------|------|------|
| `title` | ✅ | 보고서 제목 |
| `report_type` / `detail_type` | ✅ | 대분류 / 세부유형 |
| `keywords` | ✅ | 핵심 키워드 (쉼표 구분) |
| `length` | | 간략/표준/상세 (섹션당 항목 수 + 항목당 문장 수 제어) |
| `department` / `author` / `report_date` | | 문서 머리말 (HWPX 대비) |
| `facts` | | 확인된 사실·배경·현황 자유 서술 |
| `custom_sections` | | 목차 커스터마이즈 (비면 기본 목차). 프론트 목차 편집 UI에서 전달 |

### 분량 규칙 (`LENGTH_RULES`)

| 분량 | 섹션당 항목 수 | 항목당 문장 수 |
|------|--------------|--------------|
| 간략 | 3~4 | 1~2 |
| 표준 | 4~6 | 2~3 |
| 상세 | 6~8 | 3~4 |

> ⚠️ 이전 문서에는 "4개 카테고리 / 부서·배경 입력"으로 적혀 있었으나, 실제 코드 기준으로 정정함.

## 6. 수정 시 주의사항

- 보고서 유형별 작성 스타일: 서술형/나열형/효과형/방안형/분석형
- 프롬프트: `prompt_service.get("report_writer", ...)` 패턴으로 Supabase 관리 가능 (DB 우선 → 코드 fallback)
  - 관리 키: `system_prompt`, `build_prompt_template`, `type_directive:<유형명>`(5종). DB에 없어도 관리자 '프롬프트 관리'에 **코드 기본값('미저장')으로 표시·수정 가능** (`services/prompt_defaults.py` 등록)
  - ⚠️ DB에 구버전 `build_prompt_template`이 저장돼 있으면 최신 프롬프트 개선(유형지침·라벨형·금지표현 등)이 반영 안 됨 → 관리자 화면에서 최신 내용으로 갱신 필요
- 후처리 로직 (용어 교정, 마크다운 제거) 라우터 내에 있음

### 6-1. 프롬프트 설계 원칙 (내용 품질)

실제 충주시 행정문서(개조식·라벨형)에 맞춰 프롬프트를 설계함.

- **시스템 프롬프트**: 충주시 실무 톤, 사실 우선, 무근거 수치 자리표시자, 홍보체 금지
- **문체는 소제목(섹션) 성격에 따라 문장형/개조식 혼용** (종결은 항상 명사형 ~함/~임/~예정)
  - 서술형(추진배경·현황·문제점 등): 짧게 끊지 말고 2~3문장의 자연스러운 문장형, 항목 1~2개
  - 분석형·방안형·효과형(문제분석·개선방안·기대효과 등): 1~2문장 설명형
  - 나열형(개요·일정·예산·협조 등): `(라벨) 값` 항목형, 여러 항목
  - 근거: 실제 행정문서(행안부 주요업무 추진계획 등)에서 추진배경·현황·문제점은 끊지 않은 문장형, 개요·일정은 항목형으로 작성됨(WebSearch 확인). 섹션별 style은 `SECTION_STYLES`에 이미 정의
- **유형별 지시문(`REPORT_TYPE_DIRECTIVES`)**: 계획/대책/상황/분석/기타 각각의 논리 흐름(목적→현황→계획→협조→효과 등)을 주입. **유형은 사용자가 드롭다운에서 선택하는 값**이므로 CLAUDE.md의 '키워드 사전 분기 금지'(법령 챗봇 원칙)와 무관
- **라벨형 개조식**: 개요/현황 항목은 `(라벨) 값`(예: `(대상) ○○`, `(기간) 2026. ○월~○월`)
- **금지 표현**: 혁신적·최적화·시너지·체계적이고 효율적인 등 공허어 남발 금지
- **SECTION_STYLES의 example은 프롬프트에 넣지 않음**: 특정 소재(CCTV)·가짜 수치가 결과에 전이되는 문제 때문. `style`/`guide`(작성방법)만 사용하고 형식 안내는 상단 라벨형 규칙으로 대체
- **입력 부족 처리**: 사실이 부족하면 항목을 억지로 늘리지 않고 자리표시자로 남김
- **SECTION_STYLES guide의 수치 넛지 중화**: "구체적 수치와 함께" 등 무근거 수치를 유도하던 문구를 "제공된 사실의 수치가 있으면 그와 함께"로 변경(anti-hallucination과 정합)
- **허위수치 강력 차단(실측 반영)**: 실제 생성 결과 GPT가 예산·인원·비율 등을 대량 지어내는 것이 확인되어, 시스템/빌드 프롬프트에 "수치 생성 절대 금지(최우선)" + 자리표시자 형식(□□백만원/○○명/○○%/2026. ○월) + 나쁜예·좋은예를 명시하고 temperature를 0.4→0.3으로 낮춤
- **서술형 문단화 강제(실측 반영)**: 서술형 섹션이 한 문장씩 ❍로 쪼개지던 문제를 막기 위해 "content 항목을 1~2개만, 각 항목을 2~3문장 문단으로" 규칙과 나쁜예/좋은예를 추가
- **후처리 병합(결정적 보장)**: `NARRATIVE_SECTIONS`(추진배경·현황·현황분석·문제점·추진목표·기대효과·결론 등)에 해당하는 꼭지는 후처리(`_merge_narrative_paragraph`)에서 여러 ❍ 항목을 **하나의 문장형 문단으로 병합**함. 개요·일정·예산·협조 등 나열형은 항목 그대로 유지.
  - 이 병합은 라우터 코드에서 동작하므로 **DB 프롬프트 override 상태이거나 GPT가 규칙을 안 지켜도 문장형이 보장**됨
- **분량 vs 문체 정합**: `items_per_section`은 나열형 기준이며 서술형 섹션은 항목 1~2개로 축소(문장형 유지)

## 9. HWPX 내보내기 (services/hwpx_writer.py)

- **의존성**: 새 pip 패키지 없이 표준 라이브러리 `zipfile` + 기존 `lxml`만 사용 (CLAUDE.md 준수)
- **방식 (템플릿 기반)**: 손으로 짠 OWPML 대신 **실제 한글로 저장된 충주시 서식(REF)을 템플릿으로 채택**.
  - `backend/services/templates/hwpx/` 에 REF의 `header.xml`(글꼴·글자모양·문단모양·여백 정의) / `settings.xml` / `secpr.xml`(구역·여백) / `container.rdf` / `manifest.xml` / `version.xml` / `sec_open.txt`(section 루트) 저장
  - 코드는 **본문(section0.xml)만 생성**하고, 템플릿 header가 정의한 charPr/paraPr ID를 참조 → 한글 열림·서식이 참고 문서와 동일하게 보장됨
  - 템플릿 header에는 스타일 정의만 있고 원본 문서 내용·개인정보는 포함하지 않음(section0 미포함)
- **서식 (REF 추출)**:
  - 여백: 좌우 15mm / 상 20mm (secPr)
  - 글꼴·크기: 제목·□대분류 = HY헤드라인M 16pt(charPr 29), 본문 = 휴먼명조 15pt(charPr 31), 머리말 = 휴먼고딕 15pt(charPr 18)
  - **목차 기호 체계: □(대분류: 요약/섹션 제목) · ❍(중분류: 본문 항목) · -(소분류: 들여쓰기) · ※(참고)**
  - 항목의 기존 마커(가./①/○/숫자)는 레벨 판별에 사용 후 표준 기호(❍/-)로 치환, `※`로 시작하는 항목은 참고로 유지
- **문서 구조**: 제목(가운데 HY헤드라인M) → 머리말(부서·보고일자·작성자) → □요약 → □섹션 → ❍/-/※ 항목
- **검증 한계 (중요)**: CI 환경에 한글(HWP)이 없어 **구조적 유효성(zip 레이아웃·XML well-formed·charPr/paraPr/style 참조 일관성·secPr 포함)까지 자동 검증**함.
  실제 한글 렌더링 최종 확인은 사용자 몫이나, **템플릿이 실제 한글 저장본이라 열림 가능성이 매우 높음**.
- **미포함(향후)**: 결재란 표, 제목 테두리 상자, 표 형태 데이터
